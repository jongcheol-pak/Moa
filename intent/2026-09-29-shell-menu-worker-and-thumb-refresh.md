# Intent: 셸 메뉴를 워커로 옮기고 바뀐 파일의 썸네일·아이콘을 다시 만든다
Author: 사용자(jongcheol-pak). Status: approved.

## Problem
원문: "메뉴 뜨는 속도, 기존 이름으로 새 파일로 변경 되는 경우 아이콘 밋 썸네일 이미지가 바로 변경되지 않음, 목록에 기본 아이콘으로 표시되고 함참 있다가 해당 아이콘으로 표시되는 문제가 있는데 … 가끔 ui 프리징도 걸리는데 제대로 확인해서 최적화 해". 실측으로 우클릭마다 셸 메뉴 열기가 UI 스레드에서 0.3~1.8초, 하위 메뉴 호버마다 0.1~0.4초 창을 멈추고, 썸네일·경로 아이콘 캐시가 경로만 키로 삼아 복사 중(0바이트)에 받은 형식 아이콘·덮어쓰기 전 그림을 폴더를 떠날 때까지 계속 보인다. 매 우클릭에서 체감되는 결함이라 지금 고친다.

## Proposed outcome
우클릭 즉시 메뉴 뼈대(아이콘 줄·앱 줄·불러오는 중 줄)가 뜨고 셸 항목은 도착하면 채워지며, 셸 메뉴 열기·하위 메뉴 채움이 UI 스레드에서 돌지 않는다. 같은 이름의 파일이 새 내용으로 바뀌면 감시 갱신 뒤 새 썸네일·아이콘이 나온다. `MOA_PERF_LOG=1`이면 100ms 이상인 프레임이 단계별로 기록돼 메뉴 밖 프리징의 원인을 가를 수 있다. 같은 보고의 첫 항목(화면 끝에서 하위 메뉴가 부모를 덮음)은 디버깅 세션에서 고쳤고(`db5418d` — 오른쪽이 넘치면 부모 왼쪽), 그 문서 반영을 이번에 함께 한다.

## Affected users and systems
앱 사용자 본인. 셸 메뉴(`fs::shell_menu`·`ui::app::shell_menu`·`ui::shell_context_menu`·`ui::shell_host`), 썸네일·아이콘 캐시(`fs::thumbnail`·`fs::icons`·`ui::icon_tex`·목록 그리기), 계측(`perf`·`ui::app`), 규약 문서(AGENTS.md DO NOT 절).

## Constraints
셸이 메뉴를 주지 못하면 뼈대 메뉴는 앱 줄만 남긴 채 유지한다. `기본 메뉴`(표준 Win32 메뉴)는 지금처럼 UI 스레드 모달로 둔다. 계측은 꺼져 있으면 아무 비용이 없어야 한다.
