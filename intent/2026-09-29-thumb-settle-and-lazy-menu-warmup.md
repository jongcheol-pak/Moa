# Intent: 계속 바뀌는 파일의 썸네일 재생성을 멈추고 셸 메뉴 워밍업을 없앤다
Author: 사용자(jongcheol-pak). Status: approved.

## Problem
원문: "실행중 cpu,메모리등 사용량이 증가할 수 있는 부분이 있는지 검토" → 검토 결과에 "진행". 직전 회차가 썸네일을 크기·수정 시각으로 다시 만들게 하면서, 내려받는 중인 파일처럼 계속 바뀌는 파일이 썸네일 보기에 보이면 감시 갱신(약 0.3초)마다 워커가 썸네일을 다시 만들고 대체된 옛 요청까지 전부 처리한다(실측: 도장 100번 변경 → 425ms). 또 셸 메뉴 워커가 앱 시작 때 확장을 미리 불러 우클릭을 하지 않아도 +42MB·CPU 0.8~1.8초를 쓴다.

## Proposed outcome
계속 바뀌는 파일은 크기·수정 시각이 2초 동안 그대로일 때만 썸네일을 다시 만들고(그동안 CPU를 쓰지 않는다), 워커는 같은 파일에 쌓인 요청을 마지막 하나로 합친다. 셸 메뉴 워커는 앱 시작 때 확장을 불러 두지 않는다 — 비용은 첫 우클릭 때 치른다(메뉴는 뼈대로 즉시 뜬다).

## Affected users and systems
앱 사용자 본인. `fs::thumbnail`(캐시·워커)·`ui::panel`(썸네일 폴링), `fs::shell_menu_worker`(워밍업)·`ui::app` 주석.

## Constraints
처음 보는 파일의 썸네일은 지금처럼 곧바로 만든다(안정 대기는 내용이 바뀐 파일에만). 현재 시각은 바깥에서 넣을 수 있어야 한다. 반디집·PowerToys 셸 확장의 USER/GDI 누수는 코드를 바꾸지 않는다(사용자 결정).
